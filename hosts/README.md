# Host Configurations (`hosts/`)

This directory contains host-specific configurations for individual physical machines. Each subdirectory corresponds to a `hostname` declared in [`outputs.nix`](../outputs.nix).

> [!NOTE]
> **Adopting This Configuration**: External users should consult the [Adoption & Forking Guide](https://nix.kyle-kwong.com/adoption/) and use [`adopt.sh`](../adopt.sh) (`./adopt.sh <hostname> <username>`) to automatically purge personal configurations and scaffold a new host profile in this directory. There is no reason to keep `framework16` or `mini-pc-k8` unless using them as reference templates.

## Host Directory Structure

Each host directory (`hosts/<hostname>/`) adheres to a standard layout:

```text
hosts/<hostname>/
├── default.nix                 # Main host entry point
├── hardware-configuration.nix  # Auto-generated hardware configuration (do NOT edit manually)
├── disko.nix                   # Partitioning, filesystems (Btrfs), and boot decryption (TPM2/LUKS)
├── config.nix                  # (Optional) Host-specific module options and agenix secrets
└── home/                       # (Optional) Per-host Home Manager overrides
    └── default.nix
```

### File Responsibilities

1. **`default.nix`** ([framework16](./framework16/default.nix), [mini-pc-k8](./mini-pc-k8/default.nix)):
   The primary entry point imported by `outputs.nix`. Imports `disko.nix`, `hardware-configuration.nix`, and optionally `config.nix`.

2. **`hardware-configuration.nix`** ([framework16](./framework16/hardware-configuration.nix), [mini-pc-k8](./mini-pc-k8/hardware-configuration.nix)):
   Auto-generated by `nixos-generate-config` or during `install.sh`. Ignore any linter warnings inside this file and never manually modify it.

3. **`disko.nix`** ([framework16](./framework16/disko.nix), [mini-pc-k8](./mini-pc-k8/disko.nix)):
   Defines the complete block storage lifecycle:
   * Partition tables (GPT, ESP `/boot`).
   * Disk encryption (LUKS containers and optional TPM2 auto-unlock via `crypttabExtraOpts`).
   * Filesystem formatting and subvolumes (Btrfs root, home, nix, swap).
   * Storage maintenance timers (`services.btrfs.autoScrub`).

4. **`config.nix` (Optional)** ([framework16](./framework16/config.nix), [mini-pc-k8](./mini-pc-k8/config.nix)):
   A consolidated module for any machine-specific option toggles (e.g. `custom.ai`, `custom.vpn.wireguard`) and host-specific secrets (`age.secrets`). Avoid creating micro-files for individual feature toggles.

5. **`home/` (Optional)** ([mini-pc-k8](./mini-pc-k8/home/default.nix)):
   Host-specific user packages or environment settings. Automatically imported into the user's Home Manager environment by `modules/home-manager/`.

## Connection to `outputs.nix`

Every host is declared in the `hosts` set in [`outputs.nix`](../outputs.nix):

```nix
<hostname> = {
  username = "<user_name>";

  extraModules = [
    # Host-specific NixOS system modules (e.g. laptop or desktop)
    ./modules/laptop

    # Hardware tuning via nixos-hardware:
    # 1. Exact OEM device profile (e.g. inputs.nixos-hardware.nixosModules.framework-16-7040-amd)
    # 2. Or generic component profiles (e.g. common-cpu-amd, common-gpu-amd, common-pc-ssd)
  ];
};
```

## Conventions & Rules
* **No hardcoded paths or IDs**: Use dynamic `username` and the standard `users` group. Avoid hardcoded `/home/<username>` paths; reference `specialArgs.username` or config variables.
* **Keep it host-specific**: Generic or reusable capabilities belong in [`modules/`](../modules) or [`home/`](../home).
* **Per-host user configuration**: All baseline user configurations are imported directly from [`home/`](../home); host-specific user additions belong in `hosts/<hostname>/home/` (automatically imported if present).
