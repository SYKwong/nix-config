This section documents host-specific machine configurations within the fleet. Each subdirectory under `hosts/` represents an individual physical system declared in `outputs.nix`.

> [!NOTE]
> Shared modules—including Sunshine streaming with zero-touch tablet display, Hyprland, gaming, and shell scripts—are enabled by default across all fleet machines via `outputs.nix`. The table below highlights host-specific roles, hardware specifications, and quirks.

> [!TIP]
> **Adopting This Configuration**: External users should consult the [Adoption & Forking Guide](/adoption/) and run `./adopt.sh <hostname> <username>` to purge personal configurations and automatically scaffold a new host directory tailored to their hardware. There is no reason to keep the author's `framework16` or `mini-pc-k8` directories unless using them as a reference template.

## Host Directory Structure

Every host directory follows a standardized, modular layout:

```text
hosts/<hostname>/
├── default.nix                 # Primary entrypoint imported by outputs.nix
├── hardware-configuration.nix  # Kernel modules and drivers (auto-generated)
├── disko.nix                   # Partition scheme, filesystems, and encryption
├── config.nix                  # (Optional) Host-specific toggles, quirks, and secrets
└── home/                       # (Optional) Per-host Home Manager overrides
    └── default.nix
```

### File Responsibilities

1. **`default.nix`**:
   The primary NixOS configuration entrypoint for the host. Imports `disko.nix`, `hardware-configuration.nix`, and optionally `config.nix`.

2. **`hardware-configuration.nix`**:
   Auto-generated by `nixos-generate-config` or during `install.sh`.  
   > [!WARNING]
   > Never edit this file manually. Linter warnings inside auto-generated hardware configuration files are ignored by convention.

3. **`disko.nix`**:
   Defines the complete disk lifecycle:
   - Partition tables (GPT, ESP `/boot`).
   - Disk encryption (LUKS containers and TPM2 auto-unlock via `crypttabExtraOpts`).
   - Filesystem formatting and subvolumes (Btrfs root, home, nix, swap).
   - Storage maintenance timers (`services.btrfs.autoScrub`).

4. **`config.nix` (Optional)**:
   A consolidated module for machine-specific option toggles, hardware workarounds, and host-specific secrets (`age.secrets`). For example, in `mini-pc-k8`, this file configures the Realtek audio workaround and disables conflicting onboard Bluetooth controllers.

5. **`home/` (Optional)**:
   Host-specific user packages or environment settings. Automatically imported into the user's Home Manager environment by `modules/home-manager/`.

## Declaring Hosts in `outputs.nix`

Every host is wired into the system build via the `hosts` attribute set in `outputs.nix`:

```nix
<hostname> = {
  username = "<user_name>";

  extraModules = [
    # Host-specific NixOS system modules (e.g. laptop or desktop)
    ./modules/laptop

    # Hardware tuning via nixos-hardware:
    # 1. Exact OEM device profile:
    inputs.nixos-hardware.nixosModules.framework-16-7040-amd

    # 2. Or generic component profiles (if no exact device profile exists):
    # inputs.nixos-hardware.nixosModules.common-cpu-amd
    # inputs.nixos-hardware.nixosModules.common-cpu-amd-pstate
    # inputs.nixos-hardware.nixosModules.common-gpu-amd
    # inputs.nixos-hardware.nixosModules.common-pc-ssd
  ];
};
```

### Hardware Profiles (`nixos-hardware`)

When declaring a host:
- **OEM Device Profiles**: Check [NixOS/nixos-hardware](https://github.com/NixOS/nixos-hardware). Directory paths convert to module attributes by replacing slashes with hyphens (e.g., `lenovo/thinkpad/x1/6th-gen` becomes `inputs.nixos-hardware.nixosModules.lenovo-thinkpad-x1-6th-gen`).
- **Generic Architecture Modules**: For custom PCs, mini PCs (like `mini-pc-k8`), or unlisted laptops, compose common component profiles:
  - CPU: `common-cpu-amd`, `common-cpu-amd-pstate`, `common-cpu-intel`, `common-cpu-intel-pstate`
  - GPU: `common-gpu-amd`, `common-gpu-intel`, `common-gpu-nvidia`
  - Storage: `common-pc-ssd`, `common-pc-laptop-ssd`
- **Baseline Fallback**: `nixos-hardware` is optional. The kernel modules and drivers generated into `hosts/<hostname>/hardware-configuration.nix` by `install.sh` provide a fully bootable baseline without external hardware modules.

## Conventions & Best Practices

- **No Hardcoded UIDs/Paths:** Always use the dynamic `username` variable and the `users` group. Never hardcode `/home/username` or numerical UIDs.
- **Strict Separation of Concerns:** Generic or reusable capabilities belong in `modules/` or `home/`. Only true hardware-specific quirks or host-unique settings belong in `hosts/<hostname>/`.
- **Minimal Diff Churn:** Keep host configuration focused and avoid moving or refactoring unrelated blocks during host maintenance.
